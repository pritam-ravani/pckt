# PennyWise: technical guide

How PennyWise is built, for anyone working on the code. What the app does is in the [README](README.md); how to
send a fix is in [CONTRIBUTING.md](CONTRIBUTING.md).

PennyWise is a fork of [Pckt](https://github.com/pritam-ravani/pckt). Internal identifiers still say `pckt` on
purpose (see [Conventions](#conventions)).

## Quick start

| Tool | Version |
|---|---|
| Flutter | 3.47.7 (stable), with Dart 3.13.5 |
| Android SDK | platform 36, NDK 28 |
| JDK | 21 |

```sh
flutter pub get --enforce-lockfile
dart run build_runner build -d     # drift code generation
flutter run                        # phone connected with USB debugging on
flutter test                       # Dart tests
(cd android && ./gradlew :app:testDebugUnitTest)   # Kotlin tests
flutter build apk --release
```

`android/gradlew` is generated by the first `flutter build`. The generated files (`database.g.dart` and
`test/generated_migrations/`) are committed, and CI checks they are up to date.

## Architecture

- **UI and state:** Flutter (Material 3) with Riverpod 3. Screens watch drift `Stream`s through
  `StreamProvider`s, so any write shows up everywhere without manual refresh.
- **Navigation:** go_router. The bottom bar is a `StatefulShellRoute` (Home, Activity, Insights, Ask, Settings);
  other screens are pushed routes.
- **Storage:** one SQLCipher database (`pckt.sqlite`) through drift. Settings live in SharedPreferences, and
  secrets in the Android keystore through `flutter_secure_storage` (`SecretStore`).
- **Native code:** Kotlin, reached through method channels, for things Flutter can't do: reading SMS, listening
  to notifications, alarms and device details.
- **Startup work:** on every resume, `HomeShell` syncs SMS and email, drains captured payment notifications, and
  routes to Review or the add sheet if a notification asked for it.

### The ingestion pipeline

Every source produces a `RawInput`, or an already structured `(RawInput, ParsedTxn)` pair, and goes through
`IngestionService`:

```
RawInput ──► parser ──► dedup against candidates ──► merge into existing  ─┐
              │              (same amount, currency,    or insert new        ├─► raw_messages row
              │               direction, ±48 h)         + categorise         │   (parsed / merged /
              └─ ignored / unparsed (→ optional AI) ──────────────────────────┘    ignored / pendingLlm)
```

| Source | `SourceKind` | Entry point |
|---|---|---|
| SMS inbox | `sms` | `ingestion/sms`, `SmsSyncController` |
| Email (IMAP or Gmail API, in a background isolate) | `email` | `ingestion/email` |
| Manual entry | `manual` | `AppDatabase.addManual` |
| Share sheet and `pckt://ingest` links | `shortcut` | `ingestion/share` |
| Paytm Excel statement | `statement` | `ingestion/statement` → `ingestParsed` |
| Payment app notifications | `notification` | `features/capture` → `ingestParsed` |

Every raw message is kept and linked to the transaction it created or merged into, so merges can be explained,
undone and re-parsed after parser upgrades.

### Deduplication

`DedupEngine` scores each candidate:

| Signal | Effect |
|---|---|
| Same UPI ref / RRN | certain match (1.0) |
| Different refs | certain non-match (0.0) |
| Same account last digits | +0.25 (different: −0.5) |
| Time apart | +0.45 (≤5 min) … +0.1 (≤24 h) |
| Merchant tokens overlap | +0.2 (none: −0.1) |
| Different channels (SMS, email, statement, notification) with no conflict | +0.3 (≤30 min), +0.15 (≤3 h) |
| Same sender already reported it | −0.35 (two real ₹20 chais) |

A score of 0.75 or more merges automatically, and 0.5–0.75 creates a *possible duplicate* for the user to
confirm. A merchant receipt email replaces a bank's legal name ("BUNDL" → Swiggy). A debit and an equal credit
between two of your own accounts within an hour are marked as a self-transfer and left out of spending.

### Categorisation

`Categorizer` goes in this order: a merchant rule the user taught it, then structural hints (transfer, ATM,
person-to-person), then seed keywords (first match in seed order, so specific categories come before general
ones), then *Other*. A category passed in by the source, such as a Paytm tag or a tapped notification button,
wins over all of these. Optional AI categorisation only touches transactions left in *Other* or *Other Income*,
and never overrides a category the user set.

## Data

Amounts are integers in the currency's minor unit (paise, cents, whole yen) with an ISO 4217 code, so there is
no floating-point drift.

| Table | Holds | Links |
|---|---|---|
| `accounts` | banks, cards, wallets, cash; last digits for matching | |
| `categories` | name, icon, colour, income flag, order, `seed_name` | |
| `transactions` | amount, currency, converted amount, direction, time, merchant, mode, reference, status, transfer flag | → categories, accounts |
| `raw_messages` | every source message and its parse outcome; unique on (source, external id) | → transactions (set null) |
| `merchant_rules` | learned merchant → category | → categories (cascade) |
| `budgets` | monthly limit per category, or overall | → categories (cascade) |
| `payslips` | month, employer, currency, matched salary credit | → transactions (set null) |
| `payslip_lines` | earning, deduction or employer contribution lines | → payslips (cascade) |

Payslip deductions never become transactions, so they can't count against net pay twice.

### Schema and migrations

The schema is at **v6**: v4 added currencies, v5 payslips, and v6 the new seed categories. When you change the
schema:

1. Bump `schemaVersion` in `database.dart` and add an `if (from < N)` step to `onUpgrade`.
2. Dump a snapshot and regenerate the test helpers:
   ```sh
   dart run drift_dev schema dump lib/data/db/database.dart drift_schemas/drift_schema_vN.json
   dart run drift_dev schema generate drift_schemas test/generated_migrations
   ```
3. Add an upgrade test to `test/migration_test.dart`. That file also fails if a version has no snapshot.

Enums are stored by their index, so **only ever append** new values. New seed categories reach existing installs
through `_addMissingSeedCategories`, which matches by name, so nothing is duplicated.

## Features in detail

### Salary and payslips (`features/salary`)
`savePayslip` writes a payslip and its lines in one transaction; month plus employer is unique.
`autoLinkPayslips` links an unmatched payslip to a credit of exactly its net pay, from the 1st of the pay month
to the 10th of the next, picking the one nearest the pay date, and files it under Salary unless the user chose
that transaction's category. Rejecting a match turns `autoMatch` off. Editing keeps the link unless the net pay
changes, and merging transactions carries the link over. `SalaryBreakdown` sets the month's `MonthStats`
against net pay, and adds company food to the Food & Dining, Food Delivery, Tiffin & Mess and Coffee & Snacks
categories.

### Paytm statement import (`ingestion/statement`)
The `.xlsx` file is unzipped and read with `archive` and `xml` (no spreadsheet library). The history sheet is
found by its header names, amounts are parsed exactly, an unsigned amount means a transfer between your own
accounts, and the UPI reference becomes both the dedup key and `externalId`, so re-imports add nothing. Paytm
tags map to categories through `PaytmStatementImporter.tagCategories`; any other tag becomes a new category.

### Payment app notifications (`features/capture`, Kotlin)
`PaymentNotificationListener` only acts on `com.google.android.apps.nbu.paisa.user`, `net.one97.paytm` and
`com.phonepe.app`, and only when the `notif.capture` preference is on. `PaymentNotificationParser` ignores
anything failed, pending, requested, due or promotional, then queues the payment in `payment_queue.json` (in
`noBackupFilesDir`) and posts a high-priority prompt. The category buttons come from `notif.hints`, a capped
merchant → category list that the app refreshes. A button tap is recorded by `PaymentActionReceiver`. When the
app opens, `PaymentCaptureService.drain` stores each payment with confidence 0.6 (so it lands in Review), or
confirms it and learns the merchant if a category was picked.

To tune the parser: `adb logcat -s pw-notif` shows each notification's wording with names and numbers replaced
by `x` and `9`.

### Reminders (`features/reminders`, Kotlin)
Reminders are saved as JSON under `reminders.v1`. `Reminders.kt` keeps one alarm for the soonest time, using
exact alarms when allowed and inexact ones otherwise, and sets the next one each time it fires.
`ReminderReceiver` restores it after a reboot, an app update or a clock change. The text is decided when the
alarm fires, from `reminders.reviewCount` (written by the app whenever the Review count changes) plus payments
still waiting in the notification queue.

### Budgets, recurring and insights
`features/budgets` (monthly limits, alerts at 80% and 100%), `features/recurring` (cadence detection by
merchant), and `features/stats.dart` (`MonthStats`, which leaves out transfers and unconverted foreign
amounts).

## AI integration (`llm/`)

`LlmClient` has implementations for OpenAI-compatible APIs, Anthropic, Gemini and on-device LiteRT-LM
(`flutter_edge_ai`). Keys live in the keystore, and settings under `llm.*`.

- **Fallback parser:** reads messages the rules couldn't, as strict JSON, and rejects any answer whose amount
  doesn't literally appear in the message.
- **AI categoriser:** batches transactions left in *Other* and validates names against your categories.
  Confident merchant-level answers become merchant rules.
- **Ask agent:** up to 8 tool steps (4 for small on-device models) over `query_transactions`,
  `spending_summary`, `list_categories`, `list_accounts`, `find_recurring` and `recategorize`. Changes need the
  user's confirmation.
- **On-device:** the model is picked in `on_device/model_catalog.dart` from RAM, chip, storage and Android
  version. The model is kept warm and conversations are reused. Background AI is off by default on-device, and
  downloads run as a foreground service over Wi-Fi only.

## Security and privacy

- **Database:** SQLCipher 4 (AES-256), selected with `hooks: user_defines: sqlite3: source: sqlcipher` in
  `pubspec.yaml`. A random 256-bit key is created on first run and kept in the keystore. Plaintext installs
  migrate once, with row counts and integrity checks, and roll back on any failure.
- **Backups:** `BackupCrypto` uses AES-256-GCM with a PBKDF2-HMAC-SHA256 key (600,000 iterations), run in an
  isolate. The key settings are authenticated with the data, and a lost password can't be recovered. Older
  plain JSON backups still restore, and the `pckt-backup` format id is kept so they stay recognisable.
- **Android:** cloud backup and device transfer are disabled. App lock (biometric or screen lock) and
  `FLAG_SECURE` are optional.
- **Outside the encrypted database:** `payment_queue.json` until the app next opens, `notif.hints`
  (merchant → category names only), and `reminders.reviewCount`. All are in app-private storage.
- **Logs:** notification wording is logged only in masked form.
- **Network:** only to services the user turns on (mail provider, AI provider, Gmail API, Hugging Face). Fonts
  are bundled and `GoogleFonts.config.allowRuntimeFetching` is off.

## Testing and CI

- **Dart:** `flutter test` covers parsers, dedup, ingestion, currencies, migrations, encryption, backups,
  statement import, salary, notification capture, reminders, the AI clients and the agent. Database tests use
  in-memory drift databases.
- **Kotlin:** `./gradlew :app:testDebugUnitTest` covers the notification parser and the reminder schedule.
- **CI:** `.github/workflows/ci.yml` runs on pushes to `main` and on pull requests, with Flutter 3.47.7: a
  locked `pub get`, a code generation check, `flutter analyze` and `flutter test`. Kotlin tests are not in CI yet.

Release-only failures (R8) don't show up in tests, so check a release build on a real phone before merging
native changes.

## Release builds

```sh
flutter build apk --release      # R8 minify and resource shrinking
```

- **Signing:** without `android/key.properties` the APK is signed with the debug key, which is fine for
  sideloading. For a real key (never commit it: `*.jks` and `key.properties` are gitignored):
  ```sh
  keytool -genkey -v -keystore ~/pennywise-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
  ```
  then create `android/key.properties` with `storePassword`, `keyPassword`, `keyAlias=upload` and `storeFile`.
  An APK signed with a different key can't install over the old one, so export a backup first.
- **R8 rules** (`android/app/proguard-rules.pro`): plugins that Dart calls through JNI
  (`shared_preferences_android`) must keep their classes and the Kotlin types in their method signatures
  (`kotlin.coroutines.Continuation`, `kotlin.Result`, `kotlin.Unit`…). Otherwise the release build hangs on the
  splash screen.
- **Gmail sign-in (optional):** "Sign in with Google" appears only when the build has an OAuth client id. Create
  an Android OAuth client for `com.sahilkarande.pennywise` with your signing key's SHA-1, plus a Web client, and
  build with `--dart-define=GOOGLE_OAUTH_CLIENT_ID=<web client id>`. `gmail.readonly` is a restricted scope, so
  keep the consent screen in testing mode for personal use.
- **Icon and splash:** generated by `node tool/gen_brand_assets.js` (the gold-coin "P" mark).

## Conventions

- **Kept `pckt` identifiers:** the Dart package name, the Kotlin package, method channel names, the `pckt://`
  scheme, the `pckt.sqlite` file and the `pckt-backup` format all stay as they are, so existing data, links and
  backups keep working. User-facing text says PennyWise.
- **Adding a source:** produce `RawInput`s (or `ParsedTxn`s for structured data), append a `SourceKind`, and add
  it to the dedup channel set if it is an independent channel.
- **Adding a category:** add a `CategorySeed` in `default_categories.dart` (before broader categories if its
  keywords are more specific), add a schema step that calls `_addMissingSeedCategories`, and update tests that
  expect the old category.
- **Preferences read by Kotlin:** Dart's legacy store is `FlutterSharedPreferences`, with keys prefixed
  `flutter.`. Integers are stored as `Long`.
- **Privacy:** never commit statements, payslips or exports. `.git/info/exclude` can hold local patterns. Use
  masked samples in tests and issues.
